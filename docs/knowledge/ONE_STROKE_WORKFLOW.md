# 一度の依頼から品質確認・保存まで完遂する共通工程
版: 2026-11-15 / rollout-v1

## 適用範囲と優先順位
この文書は作業の進め方だけを共通化します。
現在の本人指示、対象案件の承認済み仕様・役割分担・権利・安全条件・公開条件を維持します。
軍事、薬学、三国志、政治、記事、Webの内容・表現・音声を混ぜません。
既存の正本、CURRENT、キュー、ロック、レビュー、リリース判定を使い、新しい二重管理系を作りません。
実行コードを各リポジトリへ複製する指示ではありません。

## 1. 最初に揃える情報
対象repoの最新HEAD、対象案件CURRENT、適用AGENTS、同ジャンルの採用済み成果と過去の修正記録を必要範囲で読みます。
実行中担当、task/attempt ID、保存済み結果を照合し、既存案件を新規に起動し直しません。
入力ファイルの実物・SHA、要求一覧、変更範囲、依存関係、合格条件、実行可能な能力を一つの作業パケットに固定します。
結果不明の送信・生成・アップロードは受領証と保存先を照合してから扱い、盲目的に再送しません。

## 2. 一括修正の作業工程
指摘された箇所と同じ原因が及ぶ範囲を調べ、関連する修正をまとめます。
台本→場面仕様→素材→時間軸→編集→保存の依存関係を先に確認します。
入力不足を過去の正本・実ファイル・公式資料から解消し、既存の決定を本人へ聞き直しません。
承認済み範囲の実装、機械検査、原因修正、再検査、保存、読み戻しを同じ依頼の中で進めます。
検査で不合格なら根本原因を特定し、修正内容と根拠を変えて続行します。
回数制限だけで未完成を納品せず、同じ失敗操作の反復もしません。
未変更の入力と成果物はSHA一致を確認して再利用し、変更箇所・依存箇所・隣接境界を検査します。
全編検査が案件の条件なら省略しません。

## 3. 品質の合格条件
書類やJSONの形式合格だけで、完成映像・音声・記事・アプリの品質合格を代用しません。
映像なら実映像・通常速度・字幕・素材配置・意味一致・切替・BGM・ナレーション・口パク等、対象案件で必要な項目を実物で確認します。
薬学は根拠と臨床上の意味、三国志は史実と演義の区別など、各案件の専門審査を維持します。
独立した審査を実施していない場合は、複数役の独立合議と名乗りません。
モデル名やツールの能力は実環境で確認し、利用不能な機能を実行済みにしません。
X等の最新情報は候補探索に利用し、採用判断は公式仕様・更新履歴・互換性と小規模検証で確かめます。
最新版という理由だけで動作中の依存を一斉更新せず、採用版と検証結果を固定します。

## 4. 費用と権限
不要な全再生成、全再調査、同じ失敗の再課金を避けます。
この工程の追加は、課金・認証・権限変更・既定ブランチ変更・マージ・公開の新しい許可ではありません。
本人が当該作業で承認した範囲と既存の有効な運用契約に従い、追加承認が必要な操作の前にも実施可能な準備と検証を済ませます。
「一度の依頼で完遂」は内部の検査・修正を省略する意味ではなく、本人に工程ごとの再指示を要求しない意味です。
全モデルで一発成功するという保証や、未計測の費用削減率を宣言しません。

## 5. 保存・引継ぎ・新規スレッド
成果物の実在、最終commit SHA、ファイルSHA、保存先IDまたは受領証、読み戻し結果を記録します。
未完了があれば、項目・実行者・具体的操作・依存条件・再開条件・合格条件を記録し、自分で可能な次工程は実行します。
完成は対象案件の全必須条件が実証拠で満たされた時だけ宣言します。
新規スレッドはAGENTS.md、CLAUDE.md、GEMINI.mdの該当入口からこの文書を読み、現在の案件状態を復元します。
通常のWebチャットはリポジトリを自動取得できるとは限りません。
GitHubを読む起動指示またはこの文書を含む引継ぎを必要とし、アカウント全体の設定変更や常駐workerの起動と混同しません。
マージ前は明示された作業ブランチを参照し、マージ後は既定ブランチの現行版を参照します。
